# 投递追踪：被试招募与使用说明

> 目的：把录用概率模型从"文献拼装"升级为"多被试实证验证"
> 需要：10-20 位 2027 届求职者，每人记录 10-30 个投递，秋招季每周约 5 分钟

## 为什么需要多人（而不是一个人）

单被试只能回答"这模型对我准不准"；多被试才能回答"模型本身准不准"，并且能检验三个核心命题：

| 模型命题 | 需要多人验证的方式 |
|---------|------------------|
| 院校档次（双非 vs 985 回调率差异） | 不同院校档次的被试组间对比 |
| 实力上限（投递多≠offer多） | 多人的"投递数 vs offer数"曲线 |
| 筛选裁量权（岗位类型回调差） | 控制个体后比较不同岗位类型 |

## 招募对象（要覆盖的分层）

| 分层变量 | 目标分布（20 人） | 为什么 |
|---------|------------------|--------|
| 院校档次 | 985/211 ~6，双非 ~14 | 检验双非惩罚因子 |
| 专业大类 | 理工 ~8，经管/文科 ~8，其他 ~4 | 检验专业对口因子 |
| 证书 | 有证书 ~8，无 ~12 | 检验证书因子 |
| 实习经历 | 有 ~10，无 ~10 | 检验经历因子 |
| 目标城市 | 尽量分散 | 通用性 |

## 招募话术（可直接转发）

> 我在做一个央国企求职概率模型的研究，需要 10-20 位 2027 届求职的同学帮忙记录投递数据。
> 你要做的：秋招期间每投一家，花 1 分钟在共享表格里填一行（单位、岗位、预测概率），出结果后花 30 秒回填。
> 每周最多 5 分钟，持续到 11 月。
> 你得到：一份个人投递校准报告（你的预测准不准、哪些环节卡住）+ 最终的群体研究报告。
> 数据完全脱敏：只用"院校档次/专业大类/证书有无"标签，不用真名真校。

## 使用流程

1. 复制 `docs/投递追踪模板.csv` 到共享表格（腾讯文档/石墨/飞书均可）
2. 每位被试分配一个 ID（SUB01, SUB02...），填写自己的分层标签（院校档次等，**只填标签不填真名**）
3. **投递前**：填预测列（预测回调率/预测录用率）——这是铁律，知道结果后回填预测 = 数据作废
4. **结果出来后**：回填结果列（过/拒/NA），以官方系统状态为准
5. 秋招结束后：`node tools/calibration-analysis.js` 出报告

## 数据质量铁律

1. **全样本记录**：投过的每岗都记，包括随手投的、感觉没戏的——只记"有把握的"会系统性高估
2. **前瞻性**：预测必须在投递前写死
3. **结果客观化**：以官方系统状态（已处理/笔试/面试/offer）判定，不凭感觉
4. **不修改旧记录**：预测填了就是填了，事后发现"当时高估了"也不许改——那正是要测量的误差

## 隐私承诺

- 仓库里只有模板（示例行为 SUB01 张洵脱敏），真实数据**不进 git 仓库**
- 分析只输出群体统计（分组回调率/校准差），不输出个人明细
- 被试身份仅用分层标签标识，不记录真实姓名/学校/手机号
